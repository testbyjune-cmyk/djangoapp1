Managed Agent(관리형 에이전트)는 에이전트 실행 루프, 세션 상태, 보안 샌드박스, 자격 증명 관리, 스케일링 같은 인프라를 클라우드 플랫폼이 대신 관리해주는 서버리스/PaaS 방식의 에이전트 호스팅 개념입니다. 개발자는 에이전트의 역할(Instructions)·도구(Tools)·비즈니스 로직에만 집중하면 됩니다.

핵심 개념

  • Agentic Loop 자동화: "추론 → 도구 실행 → 관찰 → 재추론"을 반복하는 과정에서 발생하는 무한 루프 차단, 컨텍스트 압축(Compaction), 프롬프트 캐싱을 플랫폼이 자동으로 관리합니다.
  • 격리된 보안 샌드박스: 세션마다 독립된 실행 환경을 제공해 데이터 유출이나 자격 증명 오염을 막습니다.
  • 자격 증명 보관소(Credential Vault): Slack·GitHub·DB 같은 외부 API 호출에 필요한 OAuth 토큰 교환과 비밀 키 관리를 플랫폼이 안전하게 대신 처리합니다.
  • 관찰 가능성(Observability): 에이전트가 어떤 이유로 어떤 도구를 호출했는지, 어디서 에러가 났는지 추적하는 표준화된 로그(OpenTelemetry 등)를 기본 제공합니다.

대표적인 플랫폼 사례

이 영역은 각 클라우드/모델 제공사가 빠르게 기능을 추가하는 중이라, 아래는 업계에서 논의되는 방향성 요약입니다. 실제 도입 전에는 반드시 공식 문서에서 최신 사양을 확인하세요.

Microsoft Foundry Agent Service

Microsoft Agent Framework(MAF)·LangGraph·OpenAI SDK 등으로 작성한 에이전트 코드를 컨테이너화해 Azure 위에 엔드포인트로 노출합니다. 코드형 "Hosted Agent"와 포털/SDK에서 프롬프트·툴만 정의하는 무코드 "Prompt Agent" 두 형태를 지원하며, MCP 및 BYOM(Bring Your Own Model)을 함께 지원합니다.

Anthropic Managed Agents

Claude 모델 기반 에이전트를 위한 호스팅 인프라 레이어로, 에이전트 흐름 제어와 코드 실행 샌드박스를 관리형으로 제공합니다. OAuth 기반 인증·자격 증명 관리를 지원하고, MCP 서버들과 연동해 커스텀 파이프라인을 직접 짜는 부담을 줄여줍니다.

1인 개발자 관점: Managed Agent로 뭘 할 수 있나? Ollama로도 될까?

회사 예산과 DevOps 팀이 없는 1인/소규모 개발자에게는 "관리형이라 편하다"는 말보다 "내 지갑과 시간에 맞는가"가 더 중요한 질문입니다. 두 축으로 나눠서 정리하면 판단이 쉬워집니다.

☁️ Managed Agent로 할 수 있는 것
  • 사이드 프로젝트를 서버 걱정 없이 실제 서비스(SaaS)로 배포 — 인프라를 안 짜도 됨
  • Slack/GitHub/구글 캘린더 같은 OAuth 연동을 자격 증명 관리 없이 빠르게 붙이기
  • 바이럴이 터져 트래픽이 급증해도 오토스케일링이 알아서 처리
  • 사용한 만큼만 내는 종량 과금이라 초기 고정비 없이 시작 가능
  • 단점: 사용량이 늘수록 비용 예측이 어렵고, 특정 플랫폼에 종속(lock-in)되기 쉬움
🖥️ Ollama(로컬)로 할 수 있는 것
  • Llama, Qwen, Mistral 같은 오픈소스 모델을 내 컴퓨터에서 무료로 실행
  • OpenAI 호환 API 형태로 열려서, 만들어둔 에이전트 코드를 거의 그대로 재사용 가능
  • 인터넷 연결 없이도 동작 — 완전한 프라이버시와 무제한 실험/반복
  • Tool calling을 지원하는 모델이면 간단한 에이전트 루프는 직접 구현 가능
  • 단점: 샌드박스·자격 증명 볼트·오토스케일링·observability는 전부 직접 만들어야 함
Managed AgentOllama (로컬)
비용사용량 기반 종량제 (커질수록 커짐)전기세 외 0원 (내 하드웨어 한도 내)
셋업 난이도낮음 — 대부분 인프라를 대신 처리낮음 — 설치 후 바로 실행되지만, 에이전트 루프는 직접 구현
프라이버시플랫폼 신뢰 필요완전 로컬 — 데이터가 밖으로 안 나감
스케일링자동, 외부 트래픽 대응 가능내 하드웨어 성능이 한계
적합한 단계실제 사용자에게 배포하는 프로덕션아이디어 검증, 프로토타이핑, 개인용 도구
1인 개발자를 위한 현실적인 전략
  • 개발·프로토타이핑 단계: Ollama로 로컬에서 무료로 반복 실험하며 에이전트 로직을 다듬는다.
  • 사용자에게 실제로 내보내는 단계: 트래픽·보안·연동이 부담스러워지는 시점에 Managed Agent로 전환한다.
  • MCP는 두 쪽 다 통한다: MCP는 특정 벤더 종속 기술이 아니므로, 로컬 Ollama 에이전트에서 만든 MCP 도구 연동을 나중에 Managed Agent로 옮길 때도 크게 바꾸지 않고 재사용할 수 있는 경우가 많습니다 — MCP 레슨 참고.
  • 처음부터 관리형에 올인하지 않기: 사이드 프로젝트 단계에서 종량 과금형 인프라를 붙이면 트래픽이 없어도 고정 학습·실험 비용이 쌓일 수 있습니다. 검증 전까지는 로컬이 안전합니다.

요약

Managed Agent는 AI 에이전트가 "프롬프트 스크립트"에서 "Enterprise-ready 서버리스 애플리케이션" 표준으로 올라섰음을 보여주는 패턴입니다. 다만 1인 개발자에게는 처음부터 필수가 아닙니다 — 검증 전에는 Ollama로 비용 없이 반복하고, 실제 사용자를 마주하는 순간 Managed Agent로 전환하는 것이 현실적인 경로입니다.
